## Desvios do plano
- A primeira execução com `HEAD` literal falhou na conferência: outro agente comitou durante o `composer install`, e o `git rev-parse HEAD` da conferência já apontava para outro commit. Repeti com o SHA fixo. O script resolve o commit uma única vez, no início, então o artefato fica correto. A conferência é que precisa usar o mesmo SHA.
- Versão no manifesto = segundo campo do nome do arquivo (`20261026_0019_…sql` → `0019`).
- `--image` constrói a partir do export limpo antes do `composer install` do pacote (o Dockerfile instala as dependências no próprio estágio `dependencies`); um único `docker build` com as duas tags `centralvet/app:<sha40>` e `centralvet/worker:<sha40>` (mesmo Dockerfile, como no compose). O `--image` só foi exercitado com `docker` falso; o build real fica para a T-15.
- O `composer install` roda com `--user $(id -u):$(id -g)` e `COMPOSER_HOME=/tmp/composer`, para os arquivos do export não ficarem com root como dono.
