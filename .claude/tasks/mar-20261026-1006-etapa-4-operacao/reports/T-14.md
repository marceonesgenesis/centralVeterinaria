## Desvios do plano
- Etapa `suite` sem bind mount de `src/`: os demais mounts do SUITE (.env.example, docker-compose.yml, docker, docs, scripts, .github) são mantidos. Motivo: `src/vendor` é ignorado pelo git, então um checkout limpo do GitHub não teria vendor; a imagem é construída do mesmo checkout na etapa `build`. Como a imagem usa `composer install --no-dev --classmap-authoritative`, os testes que sobem `php -r` em subprocesso não achavam `CentralVet\Tests\Support\*` (44 FAIL na 1ª execução real); a suíte agora roda `composer dump-autoload --dev` (sem rede; o lock não tem pacotes dev) num volume anônimo sobre `src/vendor`, descartado pelo `--rm`.
- Etapa `provision` também aplica os mesmos arquivos de schema (lidos por `provision.sh --list`, opção nova) ao banco de aplicação efêmero `centralvet` da CI, pelo usuário de migration. Motivo: 4 testes (AppointmentFormPost, PrescriptionFormArchiveLink) sobem o Adianti (`init.php`) e abrem `DB_DATABASE=centralvet`, como no dev (`Table 'centralvet.system_users' doesn't exist`). Nunca toca o banco do projeto `centralvet` (dev): só o do projeto da CI.
- Aditivos: `CI_SCRIPT_TESTS` substitui a lista da etapa `script-tests` (o run.test.sh a usa para não recursar, já que ele mesmo está na lista); linhas `lint: php -l ok files=<n>`/`lint: bash -n ok files=<n>`; em falha, `docker compose logs --tail=200 mysql redis` antes do `down -v`; falha do `down -v` vira `ci: failed step=down`; recusa `CI_PROJECT=centralvet` e `CI_WORKDIR` igual à raiz/`src`/`scripts`.
- Workflow: `timeout-minutes` 20 → 30 (build completo da imagem + suíte de 2390 testes); log completo guardado como artefato (`upload-artifact`) em falha, já que o `down -v` no trap remove os containers antes de um passo `if: failure()` conseguir ler logs.
