- Ruling: o 1º valor do python do critério é `False` desde antes da Etapa 3 (board [T-01]): translations.json segue a ordem case-insensitive (strcasecmp) exigida pelo CopilotTranslationsTest e pelo Etapa3MessagesTest; com `sorted(e, key=str.lower)` dá `True`. As chaves novas foram inseridas nessa ordem.
- Ruling: UserMessageTest.php fora de Arquivos prováveis — a contagem de STATIC (92 → 99) precisava subir para o UserMessageTest do critério passar (mesmo precedente da T-01).
- Extras de Interface (só acrescentam): `findUser(int)` (onEdit, inclui `group_id`), `listUnits()` (combo de unidade), constante `CONTROLLER = 'ClinicUserForm'` e `ClinicUserForm::makeService()` público (usado pela lista).
- Falha no envio do convite (depois do commit) vai para error_log e o id é devolvido; o usuário fica `invited` e recupera o acesso por "Esqueci minha senha" (login = e-mail). O contrato não dizia o que fazer.
- `reactivate` de usuário que não está `inactive` é no-op (sem quota); `update` troca vínculos só entre as unidades do tenant e os grupos de `allowedGroups()`, sem tocar vínculos fora desse conjunto.
- O controller usa `TConnection::open('permission')` (sem TTransaction) para o TransactionRunner fazer o commit real antes do e-mail.
- O orquestrador pediu "CSRF e RBAC": não feito aqui porque o plano (agents/jaspion.md e T-24) atribui seed, menu e inventário CSRF à T-25 e proíbe a T-24 de editá-los; as mutações já passam pela MutationRequestPolicy central (provado no wiring). Registrado no board para a T-25.
